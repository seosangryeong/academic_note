## LLM 기초

### LLM이 만들어지는 세 단계

| 단계 | 내용 |
|---|---|
| 사전학습 (Pre-training) | 인터넷 문서처럼 라벨 없는 대량의 글로 다음 단어를 맞히게 학습한다. 정답을 사람이 달 필요가 없는 **자기지도학습**이라 데이터를 크게 늘릴 수 있다 |
| 사후학습 (Post-training) | 사람이 원하는 답변 방식에 맞게 다듬는다(지시 따르기, 사람 피드백 강화학습 등) |
| 추론 시점 연산 (Test-time compute) | 답하기 전에 더 오래 "생각"하게 해서 성능을 올린다. GPT-o1 같은 추론 모델은 단계별 풀이(Chain-of-Thought)를 강화학습으로 익혀 수학·코딩 문제에서 크게 앞섰다 |

같은 모델이라도 **프롬프트**에 따라 결과가 달라진다. "단계별로 생각해 보자"처럼 풀이 과정을 쓰게 하면(Chain-of-Thought) 수학 문제 정답률이 올라가는 것이 대표적이다.

### 토큰과 생성 설정

- **토큰:** 모델이 글을 읽고 쓰는 단위. 글자 단위는 비효율적이고 단어 단위는 새 단어를 못 다뤄서, 자주 나오는 조각으로 나누는 **서브워드**(BPE: "playing" → "play" + "ing")를 쓴다. 한국어는 같은 내용이라도 영어보다 토큰이 많이 드는 편이다.
- **토큰 한도와 가격:** 한 번에 넣고 받을 수 있는 토큰 수(컨텍스트 길이)가 정해져 있고, API 요금도 입력·출력 토큰 수로 매긴다.
- **Temperature:** 답의 무작위성. 0이면 가장 확률 높은 토큰만 골라 매번 같은 답을 내고(신뢰성이 필요할 때), 1이면 학습한 분포대로, 1보다 크면 더 다양하게 고른다.
- **Top-K:** 다음 토큰을 확률 상위 몇 개 중에서만 고를지 정한다.

### 대화를 기억하는 방법

LLM 자체는 이전 대화를 기억하지 않는다. 한 번 묻고 끝나는 **싱글턴**으로 부르면 앞에서 알려 준 이름도 모른다. 대화를 이어 가는 **멀티턴**은 지금까지의 대화 전체를 매번 메시지 목록으로 같이 보내서 기억하는 것처럼 보이게 하는 방식이다. 그래서 대화가 길어질수록 토큰이 늘어난다.

### RAG (검색 증강 생성)

모델이 학습하지 않은 문서(사내 규정, 보고서 등)로 답하게 하는 방법이다.

1. 문서를 작은 조각(청크)으로 나누고, 임베딩 모델로 각 조각을 벡터로 바꿔 저장한다.
2. 질문도 같은 방식으로 벡터로 바꾼다.
3. 질문 벡터와 가장 가까운 조각 몇 개를 찾아 질문과 함께 프롬프트에 넣는다.
4. 모델은 그 조각을 근거로 답한다.

## Function Calling

LLM에게 내 함수를 알려 주고, 필요할 때 그 함수를 쓰게 하는 방법이다. 두 과제 모두 이것이 핵심이다.

1. 함수 이름, 설명, 인자 형식(JSON 스키마)을 `tools`로 모델에 함께 보낸다.
2. 모델은 바로 답하거나, "이 함수를 이 인자로 실행해 달라"는 요청(`tool_calls`)을 돌려준다.
3. 내 코드가 그 함수를 실제로 실행하고, 결과를 대화에 붙인다.
4. 모델을 한 번 더 부르면 함수 결과를 보고 최종 답을 만든다.

중요한 점은 **모델이 함수를 직접 실행하지 않는다**는 것이다. 모델은 어떤 함수를 어떤 값으로 부를지만 정하고, 실행은 내 코드가 한다. 로봇에 쓰면 LLM이 모터 값을 직접 만들지 않으므로 동작이 예측 가능하고, 위험한 동작은 함수 쪽에서 막을 수 있다. 함수는 여러 개를 함께 줄 수 있고, 모델이 한 번에 여러 함수를 순서대로 부르게 할 수도 있다.

## AI 에이전트

### 에이전트란

사용자를 대신해 복잡한 작업 흐름을 **스스로 판단하며** 끝까지 수행하는 시스템이다. 단순한 챗봇과 달리 LLM이 작업 흐름 자체를 제어한다. 다음에 무엇을 할지 정하고, 도구로 외부 시스템에서 정보를 얻거나 행동하고, 끝났는지 판단하고, 실패하면 멈추고 사람에게 넘긴다.

규칙이 너무 많아 유지보수가 어렵거나, 상황마다 미묘한 판단이 필요한 작업처럼 기존 규칙 기반 자동화로는 한계가 있는 곳에 맞다.

### 구성 요소

| 요소 | 역할 |
|---|---|
| 모델 | 추론과 의사결정을 맡는 LLM |
| 도구 (Tools) | 외부 시스템과 상호작용하는 API나 함수 |
| 지침 (Instructions) | 에이전트의 행동 방식과 제약 조건 |

좋은 도구는 세 가지 조건을 갖춘다. 에이전트의 모호한 말과 외부 시스템의 정형 데이터를 잇는 **다재다능함**, 실패해도 멈추지 않고 이어 가는 **오류 처리**, 같은 작업을 반복하지 않게 하는 **캐싱**이다.

### 여러 에이전트로 나누기

| 방식 | 내용 |
|---|---|
| 단일 에이전트 | 에이전트 하나가 도구를 늘려 가며 처리 |
| 매니저 패턴 | 관리자 에이전트가 전문 에이전트들에게 일을 나눠 주고 결과를 모음 |
| 탈중앙 패턴 | 에이전트끼리 제어권을 넘김(핸드오프). 예: 상담 에이전트가 주문 문의를 '주문 관리' 에이전트에게 통째로 넘김 |

### 안전장치와 기억

- **가드레일:** 입력과 출력을 검사해 에이전트가 정해진 범위 안에서만 행동하게 한다.
- **사람 개입:** 여러 번 시도해도 실패할 때, 또는 되돌릴 수 없는 고위험 행동(결제, 대규모 승인 등) 전에 사람에게 제어권을 넘긴다.
- **메모리:** 작업이 끝나면 사라지는 **단기 메모리**, 작업이 끝나도 남아 다음 작업에 쓰이는 **장기 메모리**, 사람·장소·개념 같은 대상별로 정보를 정리해 두는 **엔티티 메모리**가 있다.

### CrewAI

여러 에이전트를 한 팀(Crew)으로 묶어 일하게 하는 파이썬 프레임워크다.

- **Agent:** 역할, 목표, 배경을 가진 에이전트. 역할을 구체적으로 정해 주고(역할극) 미션 하나에 집중시킬수록 잘한다.
- **Task:** 에이전트에게 맡기는 일. 설명과 기대하는 결과물을 적는다.
- **진행 방식:** 일을 정한 순서대로 넘기는 **순차(Sequential)**, 관리자 에이전트가 일을 나눠 주고 검토하는 **계층(Hierarchical)**. 서로 의존하지 않는 일은 **비동기**로 동시에 돌릴 수 있다.
- **정보 전달:** 이전 작업의 최종 결과만 넘기는 **context**, 모든 에이전트의 생각·도구 사용·중간 결과를 공유하는 **memory**. memory는 맥락이 풍부한 대신 토큰을 더 쓰고 느려진다.

### 로컬 LLM과 MCP

- **Ollama:** 오픈 모델을 내 컴퓨터에서 돌리는 도구. 외부 API 대신 로컬 모델로 에이전트를 돌리면 비용이 들지 않고 데이터가 밖으로 나가지 않는다.
- **MCP (Model Context Protocol):** LLM이 외부 도구와 데이터에 연결하는 방식을 표준화한 규약. 도구를 MCP 서버로 한 번 만들어 두면 여러 LLM과 에이전트가 같은 방식으로 쓸 수 있다.
