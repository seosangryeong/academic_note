## LLM 기초

### LLM이 만들어지는 세 단계

| 단계 | 내용 |
|---|---|
| 사전학습 (Pre-training) | 인터넷 문서처럼 라벨 없는 대량의 글로 다음 단어를 맞히게 학습한다. 정답을 사람이 달 필요가 없는 **자기지도학습**이라 데이터를 크게 늘릴 수 있다 |
| 사후학습 (Post-training) | 사람이 원하는 답변 방식에 맞게 다듬는다(지시 따르기, 사람 피드백 강화학습 등) |
| 추론 시점 연산 (Test-time compute) | 답하기 전에 더 오래 "생각"하게 해서 성능을 올린다. GPT-o1 같은 추론 모델은 단계별 풀이(Chain-of-Thought)를 강화학습으로 익혀 수학·코딩 문제에서 크게 앞섰다 |

같은 모델이라도 **프롬프트**에 따라 결과가 달라진다. "단계별로 생각해 보자"처럼 풀이 과정을 쓰게 하면(Chain-of-Thought) 수학 문제 정답률이 올라가는 것이 대표적이다.

### 토큰과 생성 설정

- **토큰:** 모델이 글을 읽고 쓰는 단위. 글자 단위는 비효율적이고 단어 단위는 새 단어를 못 다뤄서, 자주 나오는 조각으로 나누는 **서브워드**(BPE: "playing" → "play" + "ing")를 쓴다. 한국어는 같은 내용이라도 영어보다 토큰이 많이 드는 편이다.
- **토큰 한도와 가격:** 한 번에 넣고 받을 수 있는 토큰 수(컨텍스트 길이)가 정해져 있고, API 요금도 입력·출력 토큰 수로 매긴다.
- **Temperature:** 답의 무작위성. 0이면 가장 확률 높은 토큰만 골라 매번 같은 답을 내고(신뢰성이 필요할 때), 1이면 학습한 분포대로, 1보다 크면 더 다양하게 고른다.
- **Top-K:** 다음 토큰을 확률 상위 몇 개 중에서만 고를지 정한다.

### 대화를 기억하는 방법

LLM 자체는 이전 대화를 기억하지 않는다. 한 번 묻고 끝나는 **싱글턴**으로 부르면 앞에서 알려 준 이름도 모른다. 대화를 이어 가는 **멀티턴**은 지금까지의 대화 전체를 매번 메시지 목록으로 같이 보내서 기억하는 것처럼 보이게 하는 방식이다. 그래서 대화가 길어질수록 토큰이 늘어난다.

### RAG (검색 증강 생성)

모델이 학습하지 않은 문서(사내 규정, 보고서 등)로 답하게 하는 방법이다.

1. 문서를 작은 조각(청크)으로 나누고, 임베딩 모델로 각 조각을 벡터로 바꿔 저장한다.
2. 질문도 같은 방식으로 벡터로 바꾼다.
3. 질문 벡터와 가장 가까운 조각 몇 개를 찾아 질문과 함께 프롬프트에 넣는다.
4. 모델은 그 조각을 근거로 답한다.

## Function Calling

LLM에게 내 함수를 알려 주고, 필요할 때 그 함수를 쓰게 하는 방법이다. 두 과제 모두 이것이 핵심이다.

1. 함수 이름, 설명, 인자 형식(JSON 스키마)을 `tools`로 모델에 함께 보낸다.
2. 모델은 바로 답하거나, "이 함수를 이 인자로 실행해 달라"는 요청(`tool_calls`)을 돌려준다.
3. 내 코드가 그 함수를 실제로 실행하고, 결과를 대화에 붙인다.
4. 모델을 한 번 더 부르면 함수 결과를 보고 최종 답을 만든다.

중요한 점은 **모델이 함수를 직접 실행하지 않는다**는 것이다. 모델은 어떤 함수를 어떤 값으로 부를지만 정하고, 실행은 내 코드가 한다. 로봇에 쓰면 LLM이 모터 값을 직접 만들지 않으므로 동작이 예측 가능하고, 위험한 동작은 함수 쪽에서 막을 수 있다. 함수는 여러 개를 함께 줄 수 있고, 모델이 한 번에 여러 함수를 순서대로 부르게 할 수도 있다.

## AI 에이전트

### 에이전트란

사용자를 대신해 복잡한 작업 흐름을 **스스로 판단하며** 끝까지 수행하는 시스템이다. 단순한 챗봇과 달리 LLM이 작업 흐름 자체를 제어한다. 다음에 무엇을 할지 정하고, 도구로 외부 시스템에서 정보를 얻거나 행동하고, 끝났는지 판단하고, 실패하면 멈추고 사람에게 넘긴다.

규칙이 너무 많아 유지보수가 어렵거나, 상황마다 미묘한 판단이 필요한 작업처럼 기존 규칙 기반 자동화로는 한계가 있는 곳에 맞다.

### 구성 요소

| 요소 | 역할 |
|---|---|
| 모델 | 추론과 의사결정을 맡는 LLM |
| 도구 (Tools) | 외부 시스템과 상호작용하는 API나 함수 |
| 지침 (Instructions) | 에이전트의 행동 방식과 제약 조건 |

좋은 도구는 세 가지 조건을 갖춘다. 에이전트의 모호한 말과 외부 시스템의 정형 데이터를 잇는 **다재다능함**, 실패해도 멈추지 않고 이어 가는 **오류 처리**, 같은 작업을 반복하지 않게 하는 **캐싱**이다.

### 여러 에이전트로 나누기

| 방식 | 내용 |
|---|---|
| 단일 에이전트 | 에이전트 하나가 도구를 늘려 가며 처리 |
| 매니저 패턴 | 관리자 에이전트가 전문 에이전트들에게 일을 나눠 주고 결과를 모음 |
| 탈중앙 패턴 | 에이전트끼리 제어권을 넘김(핸드오프). 예: 상담 에이전트가 주문 문의를 '주문 관리' 에이전트에게 통째로 넘김 |

### 안전장치와 기억

- **가드레일:** 입력과 출력을 검사해 에이전트가 정해진 범위 안에서만 행동하게 한다.
- **사람 개입:** 여러 번 시도해도 실패할 때, 또는 되돌릴 수 없는 고위험 행동(결제, 대규모 승인 등) 전에 사람에게 제어권을 넘긴다.
- **메모리:** 작업이 끝나면 사라지는 **단기 메모리**, 작업이 끝나도 남아 다음 작업에 쓰이는 **장기 메모리**, 사람·장소·개념 같은 대상별로 정보를 정리해 두는 **엔티티 메모리**가 있다.

### CrewAI

여러 에이전트를 한 팀(Crew)으로 묶어 일하게 하는 파이썬 프레임워크다.

- **Agent:** 역할, 목표, 배경을 가진 에이전트. 역할을 구체적으로 정해 주고(역할극) 미션 하나에 집중시킬수록 잘한다.
- **Task:** 에이전트에게 맡기는 일. 설명과 기대하는 결과물을 적는다.
- **진행 방식:** 일을 정한 순서대로 넘기는 **순차(Sequential)**, 관리자 에이전트가 일을 나눠 주고 검토하는 **계층(Hierarchical)**. 서로 의존하지 않는 일은 **비동기**로 동시에 돌릴 수 있다.
- **정보 전달:** 이전 작업의 최종 결과만 넘기는 **context**, 모든 에이전트의 생각·도구 사용·중간 결과를 공유하는 **memory**. memory는 맥락이 풍부한 대신 토큰을 더 쓰고 느려진다.

### 로컬 LLM과 MCP

- **Ollama:** 오픈 모델을 내 컴퓨터에서 돌리는 도구. 외부 API 대신 로컬 모델로 에이전트를 돌리면 비용이 들지 않고 데이터가 밖으로 나가지 않는다.
- **MCP (Model Context Protocol):** LLM이 외부 도구와 데이터에 연결하는 방식을 표준화한 규약. 도구를 MCP 서버로 한 번 만들어 두면 여러 LLM과 에이전트가 같은 방식으로 쓸 수 있다.

## 중간과제: LLM으로 캔 찾아 집기 (Webots) {#midterm .part}

!!! summary "한 줄 요약"
    Webots 시뮬레이터에서 바퀴 달린 로봇이 **"탐색하다가 캔을 발견하면 캔을 잡아줘"** 같은 자연어 명령을 받아, 장애물을 피하며 돌아다니다 카메라로 캔을 찾으면 다가가 집어 올리게 했다. 명령은 OpenAI API의 Function Calling으로 `move_robot`, `pick_can`, `drop_can` 세 함수 중 하나로 바뀐다. 캔 집기와 옮긴 뒤 내려놓기를 각각 25번씩 시험해 모두 성공했다.

### 시나리오

| 단계 | 로봇이 하는 일 |
|---|---|
| 이해 | 자연어 명령을 읽고 "캔 탐색"을 시작 |
| 탐색·회피 | 거리 센서로 장애물을 피하며 맵을 돌아다님 |
| 발견·접근 | 카메라에 캔이 보이면 캔 쪽으로 다가감 |
| 수행 | 그리퍼로 캔을 집어 들어 올리고, LED를 켜서 잡은 상태를 표시 |

### 로봇 모델

![로봇 모델](assets/mid-robot.jpg){ width="420" }
*Webots에서 만든 로봇. 앞의 노란 판 두 개가 그리퍼, 위의 파란 상자가 카메라.*

| 부품 | 역할 |
|---|---|
| 바퀴 모터 2개 (좌·우) | 이동. 두 바퀴 속도 차이로 회전 |
| 그리퍼 리니어 모터 2개 (좌·우) | 캔 잡기 |
| 수직 리니어 모터 | 잡은 캔 들어 올리기 |
| 카메라 | 캔 인식 |
| 거리 센서 3개 (가운데·왼쪽·오른쪽) | 장애물 감지 |
| LED | 잡은 상태 표시 |

### 시스템 구성

| 단계 | 하는 일 |
|---|---|
| 1. 사용자 | 웹 화면(Robot Window)에 자연어 명령 입력. 앞/뒤/좌/우 버튼도 있음 |
| 2. 로봇 컨트롤러 | 명령을 OpenAI API에 보내 어떤 함수를 부를지 받아 옴 |
| 3. 함수 실행 | 고른 함수대로 바퀴·그리퍼·LED 모터를 움직이고, 카메라와 거리 센서 값을 읽음 |
| 4. 상태 표시 | 현재 상태("캔 탐색 중", "드롭 대기" 등)를 웹 화면에 다시 보냄 |

![Webots 시뮬레이션 화면](assets/mid-webots.jpg)
*왼쪽이 Webots 맵(바위 장애물과 캔), 오른쪽이 명령을 넣는 웹 화면. 왼쪽 위 작은 창이 로봇 카메라 화면이다.*

### 핵심 기법

#### Function Calling

| 함수 | 인자 | 동작 |
|---|---|---|
| `move_robot` | 방향, 속도, 시간 | 정한 방향으로 정한 시간만큼 이동 |
| `pick_can` | | 캔 탐색 → 장애물 회피 → 접근 → 잡기 → 들기를 이어서 수행 |
| `drop_can` | | 들고 있던 캔을 내려놓음 |

"캔을 집어 → 뒤로 3초간 이동 후 캔 내려놔 → 뒤로 가"처럼 여러 단계 명령도 함수 호출 여러 개로 나눠 차례로 실행한다.

#### 조건부 센서 사용

- 카메라에 캔이 **안 보이면** 거리 센서를 켜고 장애물을 피하며 탐색한다.
- 캔이 **보이면** 거리 센서를 무시하고 캔으로 곧장 다가간다. 캔도 거리 센서에는 장애물로 잡히기 때문에, 이렇게 하지 않으면 캔 앞에서 피해 버린다.

#### 장애물 회피

- 가운데 센서에 장애물이 잡히면 왼쪽·오른쪽 센서 중 **더 멀리 비어 있는 쪽**으로 돈다.
- 로봇이 한동안 움직이지 않으면(구석에 끼임) **뒤로 물러난 뒤 돌아서** 빠져나온다.

### 결과

| 시험 | 성공률 |
|---|---|
| 카메라에 캔이 보이는 상태에서 집기 | 100% (25/25) |
| 캔이 안 보이는 상태에서 탐색 후 집기 | 100% (25/25) |
| 집은 채로 후진한 뒤 내려놓기 | 100% (25/25) |
| 집은 채로 전진한 뒤 내려놓기 | 100% (25/25) |
| 집은 채로 회전한 뒤 내려놓기 | 100% (25/25) |

### 한계와 개선

| 한계 | 개선 방향 |
|---|---|
| 장애물이 적고 모양이 단순했다. 의자나 책상처럼 아래가 뚫린 장애물은 거리 센서로 잡기 어렵다 | 라이다로 감지 |
| 맵을 만들지 않아서, 캔을 원하는 위치에 가져다 놓을 수 없다 | GPS나 라이다로 지도를 만든 뒤 원하는 위치에 내려놓기 |
| 이미 지나간 곳을 다시 탐색할 수 있다 | SLAM 등으로 탐색한 영역을 기억 |

## 기말과제: 우주선 안 모바일 매니퓰레이터 LLM 제어 (Isaac Sim) {#final .part}

!!! summary "한 줄 요약"
    무중력 우주선 내부를 Isaac Sim으로 만들고, 레일 위를 오가는 **Franka Panda 로봇팔**이 **"버튼 눌러줘"**, **"레버 내려줘"** 같은 자연어 명령을 받아 움직이게 했다. LLM은 Function Calling으로 레일 이동, 회전, 팔 동작 함수를 고르고, 팔의 역기구학은 ROS 2의 **MoveIt 2**가 풀어 Isaac Sim에 관절 명령을 보낸다. 위치가 고정된 버튼과 레버는 매번 성공했다.

### 목표와 시나리오

**목표:** 중력이 없는 우주선 안에서 사람이 직접 움직이는 것보다 빠르고 정확하게, 자연어 명령만으로 로봇이 일하게 한다.

| 시나리오 | 동작 |
|---|---|
| 버튼 누르기 | 로봇팔로 벽의 버튼을 누름 |
| 레버 내리기 | 로봇팔로 레버를 위에서 아래로 내림 |
| 복귀 | 일을 마친 뒤 처음 위치로 돌아옴 |

### 로봇 구조

![레일 위의 Panda 로봇팔](assets/final-robot.jpg)
*바닥의 레일(직선 관절)과 기둥(회전 관절) 위에 얹은 Franka Panda.*

| 부분 | 내용 |
|---|---|
| 로봇팔 | Franka Emika Panda: 사람 팔과 같은 7 자유도 |
| 직선 관절 (Prismatic) | 레일을 따라 로봇 전체를 앞뒤로 이동 |
| 회전 관절 (Revolute) | 기둥을 돌려 팔이 향하는 방향을 바꿈. 바닥 가까운 물체에도 팔이 닿게 함 |

무중력 상태에서는 다리나 바퀴로 바닥을 밀어 움직일 수 없어서, 우주선에 고정된 레일을 따라 움직이는 구조로 했다.

### 시스템 구성

| 단계 | 하는 일 |
|---|---|
| 1. 사용자 | 자연어 명령 입력. 예: "로봇을 5 m 이동한 후 시계방향 90도 회전하고 로봇팔을 (0.3, 0.2, 0.3)으로 이동해줘" |
| 2. OpenAI API | 명령을 함수 호출로 바꿈. 예: [레일 5 m 이동 → 회전 관절 시계방향 90도] + [엔드이펙터를 (0.3, 0.2, 0.3)으로] |
| 3. 제어 노드 (ROS 2) | 레일·회전 관절은 목표값(예: `[5.0, −π/2]`)을 바로 보내고, 팔 목표 위치는 MoveIt 2에 넘김 |
| 4. MoveIt 2 | 목표 위치까지의 궤적을 만들고 역기구학으로 관절 각도를 계산 |
| 5. Isaac Sim | 관절 명령대로 움직이고, 현재 관절 상태를 다시 내보냄 |

#### Isaac Sim – MoveIt 2 동기화

![MoveIt 2와 Isaac Sim 동기화 화면](assets/final-moveit.jpg)
*왼쪽이 MoveIt 2(RViz), 오른쪽이 Isaac Sim. 같은 자세를 유지한다.*

Isaac Sim에서 각 관절의 현재 위치를 받아 MoveIt 2의 로봇 상태를 맞춘다. MoveIt 2는 그 상태에서 목표까지 궤적을 만들고, 계산한 관절 값을 Isaac Sim에 관절 명령으로 보낸다. 시뮬레이터와 계획기가 같은 자세를 보고 있어야 계획한 궤적대로 움직인다.

### 핵심 기법

#### Function Calling

| 함수 | 동작 |
|---|---|
| 레일 이동 | 직선 관절을 지정한 거리만큼 이동 (예: "레일 −2 m 이동", "레일 4 m 이동") |
| 회전 | 회전 관절을 지정한 방향과 각도로 회전 (예: "시계방향 30도 회전", "반시계방향 90도 회전") |
| 팔 조작 | 엔드이펙터를 지정한 좌표로 이동 |

#### 연속 동작

명령 하나로 여러 함수를 이어서 실행한다.

| 명령 | 실행되는 동작 |
|---|---|
| "버튼 눌러줘" | 레일 7.5 m 이동(버튼과 같은 위치) → 기둥을 시계방향 π/3 회전(버튼 쪽) → 팔을 뻗어 버튼 누르기 |
| "레버 내려줘" | 레일 8.4 m 이동(팔이 레버에 닿는 거리) → 팔로 레버를 위에서 아래로 내리기 |

### 결과

- 무중력 상태이고 버튼·레버처럼 우주선에 고정된 물체는 월드 좌표가 바뀌지 않으므로, 두 동작 모두 **매번 성공**했다.
- 처음 상태(레일 0 m, 회전 0 rad)로 돌아가라는 명령은 **문장 표현에 따라 LLM이 알아듣지 못했다.**

| 표현 | 결과 |
|---|---|
| 원점으로 / 초기위치로 / 원상태로 / 원래 위치로 | 실패 |
| 원래상태로 / 홈으로 | 성공 |

### 한계와 개선

| 한계 | 개선 방향 |
|---|---|
| 정해진 위치의 물체만 다룰 수 있다 | 카메라나 라이다로 물체를 인식한 뒤 제어 |
| 미리 정해 둔 관절 각도로 팔을 움직여서, 경로에 장애물이 있으면 걸린다 | 센서로 장애물을 인식하고 A*, RRT 같은 경로 계획으로 피해 가기 |
| 물체를 집어 옮기는 동작이 없다 | 물체 인식 후 그리퍼로 Pick and Place. 무중력에서는 작은 힘에도 물체가 계속 밀려가므로 확실하게 잡는 파지 방법이 필요 |
